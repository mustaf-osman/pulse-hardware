## 3. 架构：硬件怎么接到软件

```text
[ ESP32-S3 固件 ]
      │  Wi-Fi 同一局域网
      │  HTTP  (主路径，已落地)
      │  可选 WS /nimo/ws（语音）
      ▼
[ Nimo / Pulse 本机服务 :3721 ]
  src/api.js          ← Device API、语音队列、WS
  src/device-speech.js
  src/ui/brain-ui/device-view.js  ← 设备中心
      │
      ▼（商业授权，与板子直连无关）
[ newpulse-cloud ]
```

**短期官方建议：HTTP 轮询，不要一上来就上 MQTT。**

最小闭环：

1. 电脑 `npm run start:lan`  
2. 板子连同一 Wi-Fi  
3. `POST /device/register`  
4. `GET /device/config`  
5. 定时 `POST /device/heartbeat`  
6. 定时 `GET /device/next-reminder` → 屏显  
7. 用户操作 → `POST /device/complete` 或 `/device/snooze`  

语音增强路径（主固件已部分接入思路）：

- `GET /device/speech/next` → `GET /device/speech/audio?id=` → I2S 播放 → `POST /device/speech/ack`

## 4. 设备协议速查（以代码为准）

实现主文件：`src/api.js`（搜 `/device/`）。

| 方法 | 路径 | 用途 |
|------|------|------|
| GET | `/device/info` | 服务器、设备列表、协议清单 |
| POST | `/device/register` | 开机注册 |
| POST | `/device/heartbeat` | 心跳 |
| GET | `/device/config?deviceId=` | 轮询/心跳间隔等 |
| GET | `/device/status` | 状态 |
| GET | `/device/screen-status?deviceId=` | 屏幕相关状态 |
| GET | `/device/next-reminder?deviceId=` | 下一条 active 提醒 |
| POST | `/device/complete` | 完成提醒 |
| POST | `/device/snooze` | 稍后 |
| POST | `/device/test-push` | 测试推送（不改真实提醒逻辑需看实现） |
| GET | `/device/stream?deviceId=` | SSE |
| GET | `/device/speech/next` | 下一条待播语音 |
| GET | `/device/speech/audio?id=` | 拉音频 |

## 5. 硬件与引脚（主固件已写死的关键信息）

来源：`firmware/nimo-esp32s3-minimal/nimo-esp32s3-minimal.ino`  
以及 speaker-test README。

### 板型与 Arduino 设置

- 开发板：`ESP32S3 Dev Module`
- PSRAM：`OPI PSRAM`（喇叭测试要求）
- Flash：`16MB`（喇叭测试要求）
- 串口监视器：`115200`
- 历史上本机曾识别为 **COM11**（换电脑/口请重选）

### LCD（ST7789）

- MOSI=`47` SCLK=`21` CS=`2` DC=`3` RST=`-1`（复位可能走扩展芯片）

### XL9555（I2C 扩展，地址 `0x20`）

- SDA=`38` SCL=`48`
- LCD CS / 背光 / 音频静音等在 P15/P16/P17 一带（见固件常量）
- KEY1：`P04`，低有效；板载 BOOT 键 GPIO0

### 音频 ES8311 + NS4150B

- 控制 I2C：SDA=`4` SCL=`5`，地址 `0x18`
- I2S：MCLK=`45` BCLK=`39` LRCK=`41` DOUT=`42` DIN=`40`
- PA MUTE 曾存在「候选脚拉高」探测；主固件用 XL9555 `AUDIO_MUTE` 路径使能

### 私有配置（不要把真密码提交公开仓库）

复制示例：

```text
firmware/nimo-esp32s3-minimal/private_config.example.h
  → private_config.h
```

必填项：

```cpp
WIFI_SSID / WIFI_PASSWORD
NIMO_BASE_URL   // 例: http://<电脑局域网IP>:3721
DEVICE_ID       // 例: nimo-esp32s3-001
DEVICE_NAME
```

**每次换网络只改 `private_config.h`，尽量别改主 `.ino` 逻辑。**

## 6. 今天就能接着干的标准流程

### A. 软件侧上电（电脑）

```powershell
cd G:\emo
npm install          # 若依赖已齐可跳过
npm run start:lan    # 必须 LAN，不要只绑 127.0.0.1
```

1. 记下电脑局域网 IP（设备中心页面也会提示接入地址）  
2. Windows 防火墙放行 Node/端口 **3721**  
3. 打开 Brain UI → **设备** 页，确认 LAN URL  
4. （可选）`npm run smoke:device`

### B. 固件烧录

1. Arduino IDE 打开 `firmware/nimo-esp32s3-minimal/`  
2. 配好 `private_config.h`（SSID、密码、`NIMO_BASE_URL`）  
3. 选端口上传；若卡在 Connecting，按住 **BOOT** 再点上传，见 Connecting 后松开  
4. 串口 `115200`，期望看到：
   - `WiFi connected`
   - `POST /device/register -> 200`
   - `POST /device/heartbeat -> 200`
   - `GET /device/next-reminder -> 200`
5. 设备中心刷新，应看到设备在线  

### C. 若喇叭/音频不通，先单独验

烧录 `firmware/nimo-esp32s3-speaker-test/`，确认 I2C 找到 `0x18` 且有 440Hz 持续音，再回到主固件接 `/device/speech/*`。

### D. 功能验收清单

- [ ] 同网段，电脑 LAN 模式可被板子 ping/访问  
- [ ] 注册成功，设备页在线（约 90s 内心跳）  
- [ ] 软件侧建一条 active 提醒，板子能拉到并显示  
- [ ] 完成 / 稍后 能回写软件状态  
- [ ] （进阶）speech 队列能播、ack 正常  
- [ ] （进阶）`/nimo/ws` 语音通路按需开启，注意 `voice/capture` 默认可能关闭

## 8. 现场排障速查

| 现象 | 优先检查 |
|------|----------|
| 板子连不上 API | 是否 `start:lan`；IP 是否写对；防火墙；是否同一 Wi-Fi（访客网络隔离） |
| 注册无 200 | `NIMO_BASE_URL` 末尾不要乱加路径；串口看 HTTP 错误体 |
| 设备页看不到在线 | 心跳是否在跑；90 秒窗口；页面是否刷新 |
| 烧录 Connecting 卡住 | BOOT 键时序；换线/口；驱动 |
| 有屏无声 | 先跑 speaker-test；查 `0x18`；XL9555 静音脚 |
| `ESP_I2S.h` 找不到 | Arduino ESP32 板支持升到 3.x |
| better-sqlite3 / 脚本异常 | 部分检查需 Electron runtime；见分析文档说明 |

## 9. 和云端的边界（避免接错线）

- **硬件调试阶段**：板子只打本机 `http://<LAN-IP>:3721`，不打 cloud。  
- **newpulse-cloud**：管账号登录、订阅、单设备绑定电脑、强制下线。  
- 第一阶段云端**不同步**提醒业务数据到云；硬件提醒链路是本地 Nimo。
